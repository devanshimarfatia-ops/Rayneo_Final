## 9.1 MVP 目标

在设备上用一次短时游玩证明核心循环成立：现实中的工作赚金币，小岛自己探索，宝箱给卡牌，金币换成长，离开 app 后进度不丢。

MVP = 演示展示版。可发布版本：[ ]（MVP 试玩之后再定）。

演示日期：[ ]。演示时长：10 分钟（新手引导 + 正常游玩 + 一次退出再进入）。设备：一台 RayNeo X3 Pro，一个房间。观众在新手引导中自己设锚点；演示完一位后用 Reset 清空，给下一位重新开始。

## 9.2 演示路径与验收标准

前置条件：全新安装，或已执行 Reset（没有存档、没有锚点）。系统 To-do app 里可以预先放 1–2 条待办，作为没有网络时的备用（D5）。

| # | 步骤 | 玩家操作 | 验收标准（可在设备上测试） |
|---|---|---|---|
| 1 | 启动 | 打开 app，点击 Start | 没有存档时直接进入新手引导。3 秒内出现第一张提示。没有报错提示。 |
| 2 | 操作教学 | 按提示点击、滑动、双击 | 三种操作各有一张提示卡，做对后自动进入下一步。任何时候都可以跳过引导。 |
| 3 | 设锚点 | 站到工作位置，新建并命名第一个分区（Work） | 锚点建好后出现确认提示；离开 2 m 再回来，能重新识别为 Work 区。 |
| 4 | 添加待办 | 用语音新建（`startTodo`），或从已有待办里选一条 | 新待办归到 Work 区（D3），出现在左上角。没有网络时可以改选已有待办，引导不会卡住（D5）。 |
| 5 | 完成待办 | 选中任务，点击完成 | 任务被划掉，系统 To-do app 中同步标为已完成，金币 + 固定的任务奖励。 |
| 6 | 工具菜单 | 按提示找到正前方下方的工具菜单 | 菜单跟随视线，位于正前方下方；提示在找到后消失。 |
| 7 | 转向小岛 | 头向右转 | 小岛出现在右侧，头动时保持在原位。角色在短时间内发现教程宝箱（引导用的固定时长，不走经济表的探索时间），宝箱进度条同步走满。 |
| 8 | 打开教程宝箱 | 聚焦宝箱，点击 | 固定发放：一份金币 + 一张 Common 卡 + 一个卡包（GDD 2.1）。奖励只发放一次；跳过引导时宝箱留在岛上，不自动发放。 |
| 9 | 打开卡包 | 点击卡包 | 翻开五张卡。新卡标 NEW；重复卡显示转换成的金币。 |
| 10 | 图鉴 | 打开图鉴，再返回 | 新卡可见，带稀有度颜色。滑动切换焦点。双击返回。引导到此结束，进入正常游玩。 |
| 11 | 升级 | 打开商店，购买一级 Coin Rate | 金币按价格扣除。HUD 上的被动产出速率立即提高。金币不够时无法购买。 |
| 12 | 退出再进入 | 退出 app，重新打开，点击 Start | 不再进入引导。不论离开多久（10 秒也算）都弹出离线结算提示：金额 = 存档时的产出速率 × min(离开时长, 24 h)，与公式结果一致，保留小数点后 10 位（不足 1 时显示为 0.xxxxxxxxxx）；只有这条提示显示小数，HUD 等其他地方只显示整数（向下取整），内部余额保留小数。只结算一次。金币、卡牌、升级等级、任务状态、宝箱状态都和退出前一致（另加离线收益）。Work 区仍能识别；如果锚点没能保留，走 R1 的手动选分区。 |
| 13 | Reset | 设置 → Reset → 确认 | 需要二次确认。清空本游戏的存档和锚点，不删除系统 To-do app 里的待办。重置后回到第 1 步。 |

演示通过 = 13 步在一次流程里全部成功（10 分钟内），连续两次（中间用 Reset），不借助 adb 或 Editor。

## 9.2b 演示模式（收益加速）

目的：进度由使用时间驱动，所以展示时要把收益加速给观众看。演示模式不改系统时间，也不改游戏读到的时间：它只是给收益速度（被动金币 + 宝箱探索进度）乘一个倍率。

- 三档速度，每档有不同的观感目标（倍率按经济初稿的"每个宝箱 5 小时"推算）：

| 档位 | 收益倍率 | 角色动画速度 | 观众看到的效果 |
|---|---|---|---|
| 1 档 | 1x | 1x | 正常速度。 |
| 2 档 | 60x | 2x | 角色明显走得更快，金币明显涨得更快（约 2 金币/秒）；宝箱进度条约 5 分钟走满一次。 |
| 3 档 | 1800x | 3x（上限） | 宝箱进度条约 10 秒走满：从开始搜索到发现宝箱的全过程在 10 秒内看完。3 个宝箱位约 30 秒全满。 |

- 另有"跳过离线 N 小时"：直接按 N 小时的收益走一次正常的离线结算（同样的公式和 24 h 上限），不改任何时间。
- 倍率只作用于被动金币和宝箱探索进度。离线结算、提示时长、输入、存档间隔都按真实时间。角色动画按上表另外加速，并设上限，避免看不清。
- 倍速标记：档位 ≠ 1 档时一直显示（比如角落里的 "60x DEMO" / "1800x DEMO"，放在安全边距内），让观众知道画面是加速的。
- 正式版本中默认关闭，通过隐藏开关打开（比如在时钟上连续点击某个序列，或开发版编译开关）。演示模式不写正式存档，使用单独的演示存档位。

验收标准：
- 3 档下，宝箱进度条从 0% 到发现宝箱用时 10 秒（±1 秒）；2 档下约 5 分钟。
- 2 档下，角色移动速度明显快于 1 档（2 倍）。
- 游戏内 N 小时后的金币、已发现宝箱数、能否买得起升级，与经济表 "Timeline" 页的数值相差不超过约 5%。
- "跳过离线 N 小时"的结果与真实离开 N 小时相同（同样的结算，同样的 24 h 上限）。
- 切回 1x 后进度全部保留，倍速标记消失。

## 9.3 各系统范围

| 系统 | MVP 包含 | 不做（v2） | 砍掉的理由 |
|---|---|---|---|
| 锚点 / 分区 | 3 个锚点（Work / Kitchen / Bedroom，沿用现有原型），引导中新建并命名第一个，进出检测，分区任务浮层 | 第 4 个锚点，重叠优先级，重命名界面 | 现有原型已经是 3 个区，检测能用；第 4 个只增加测试成本。 |
| 待办 | 读取系统列表，完成任务 → 金币，通过 `startTodo` 语音新建，本地分区标签 | 游戏内删除/编辑，离线录入任务，通用待办面板规则 | 完成 + 奖励就是循环本身；编辑功能属于工具层打磨。 |
| 番茄钟 | 只做图标：放在主视野的工具栏里，具体功能先不做（D7） | 计时功能（默认 45 分钟，可暂停、可跳过；独立工具，不跟分区联动），完成奖励，30% 提前结束规则，休息提醒 | 图标让工具栏完整，体现"工具优先"；计时和奖励证明循环用不到。 |
| 时钟 | 工具菜单里显示简单时间 | 样式 | 很简单，能体现"工具优先"。 |
| 小岛 / 探索 | 1 个岛，1 个角色，最多 3 个宝箱，定时发现，离线时发现已有宝箱，宝箱进度条。宝箱生成：从几个固定生成点里随机选一个；搜索期间用带"?"的虚线轮廓（≥2 px）标出位置；搜索时间到，宝箱掉落到位，轮廓消失。 | 在岛上任意位置完全随机生成，小岛皮肤（商店），地图解锁，环境事件 | 完整版也只有一个岛。生成标记放进 MVP：2D 下成本低，而且在 1800x 演示档里观众能看清宝箱会落在哪。 |
| 宝箱 | 固定奖励表（3 份奖励，金币/卡牌/卡包） | Luck 属性效果，稀有度保底，淡入动画打磨 | Luck 是 v2 的升级项。 |
| 卡牌 / 卡包 | 用现有插画做卡组，3 种稀有度，卡包 = 5 张卡，重复卡 → 金币 | 翻卡小游戏，猫猫梗卡组，在商店购买卡包 | 用 Devanshi 分支 `origin/Devanshi` 里 `Assets/Art Assets/` 的 8 张插画（artwork_01–08）；商店卖卡包会增加平衡工作量。 |
| 图鉴 | 全部卡牌的网格，锁定/解锁状态，卡牌查看器 | 排序，筛选，容量规则 | 查看器在 Devanshi 的分支上已经有了。 |
| 升级 | 只做 Coin Rate | Exploration、Luck、皮肤（包括跟随角色的宠物），装饰 | 一个属性就能证明"花钱"这一环。 |
| 每日登录 | 不做 | 每日金币，5 天卡牌奖励 | 需要连续多天游玩，10 分钟演示里展示不了。 |
| 新手引导 | GDD 2.1 的引导流程：操作教学、设锚点、添加待办、工具菜单、教程宝箱、卡包、图鉴；可随时跳过 | 番茄钟介绍那一步，重玩引导 | 引导是演示的主体，观众要自己设锚点。番茄钟不在 MVP 里，对应步骤一起去掉。 |
| 设置 | Reset（二次确认；清空本游戏存档和锚点，不删系统待办） | 3 个存档槽（新建/删除），重玩引导，音频设置 | 演示只需要"清空给下一位"；存档槽要做选槽界面，留到 v2（D10）。 |
| 美术 | 2D 循环动画：小岛、角色搜索、宝箱都用 2D 序列帧 / sprite 动画；按稀有度区分的卡框；按 RayNeo 规范做的 HUD | 3D 小岛和 3D 角色（后续可考虑），小岛皮肤（商店），季节视觉，装饰美术 | 2D 循环动画开发成本低；现有的 3D 小岛模型先不用。 |
| 音频 | 不做（或者只给开宝箱加一个音效） | Lo-fi 音乐，音效包，静音 | 工作量；证明循环用不到。 |

宝箱进度条（新增，MVP 包含）：
- 一条横向进度条，位于小岛下方，显示角色找到下一个宝箱的进度；走满 = 发现宝箱，然后从 0 开始找下一个。用条形，不显示百分比数字。
- 3 个宝箱位都满时，进度条停在满格，显示短提示"宝箱已满"，提醒玩家去开宝箱；开掉一个后继续搜索。
- 退出再进入后，进度条显示离线期间推进后的位置。
- 按 RayNeo 规范：线宽 ≥ 2 px，青色填充，无渐变。Exploration 升级（v2）缩短的是走满所需时间。

## 9.4 开工前需要定的决策

| # | 决策 | 推荐默认方案 | 影响 |
|---|---|---|---|
| D1 | 核心循环：GDD 版（待办 → 金币，卡牌来自宝箱）还是 `milestone_A_tuesday` 版（待办 → 插画变清晰 → 解锁到图鉴） | 用 GDD 的循环。不用马赛克/模糊效果：开宝箱和卡包时卡牌直接显示；图鉴里未获得的卡显示剪影，获得后直接全彩（参考《王国：两位君主》地图的已解锁/未解锁效果）。 | 卡牌、图鉴、待办衔接 |
| D2 | DoF 模式 | MVP 全程开 SLAM（6DoF）：分区检测一直有效，小岛固定在空间里。耗电、发热等硬件性能问题 MVP 阶段不考虑，只专注玩法。 | 小岛摆放、锚点 |
| D3 | 分区任务的存储 | 分区写进待办文字本身，不另存映射表。在游戏内某个分区新建的待办，建好后立刻用 provider 的 `todoEdit` 把文字改成 `(分区)-内容`，例如 `(Work)-写报告`，系统 To-do 里也这样显示。游戏读取时解析开头的 `(分区)-`，只在该分区显示，显示时去掉前缀。在游戏外（系统 To-do）直接添加、或前缀被改坏的待办，一律算 General。分区信息跟着系统待办走，Reset 或重装游戏都不会丢。`todoEdit` 还没在真机上验证过（W7 第一步先测）。 | 分区 → 待办衔接 |
| D4 | 暂停 / 失焦（`startTodo`、系统弹窗、熄屏、摘下眼镜）和真正退出怎么区分 | 只有 app 被关闭或被系统杀掉才算真正退出。暂停多久都算同一次会话：不弹离线结算提示；恢复时按暂停时长把这段的金币和探索进度直接补上（同样受 24 h 上限约束）。每次暂停都存档。离线结算提示只在真正退出后重新打开时出现。暂停期间被系统杀掉的，下次启动按暂停时存档的时间做离线结算。 | SaveSystem、番茄钟 |
| D5 | 没有网络时的新手引导 | 新手引导永远不强制用语音。待办这一步用系统里已有的待办，或本地存的示例任务。语音新建作为可选项展示。 | 新手引导 |
| D6 | 卡牌数量和 3×3 图鉴 | 每种稀有度 3 张：3 普通（Common）/ 3 珍藏（Treasured）/ 3 特殊（Special），共 9 张，正好填满 3×3 网格。现有 8 张插画 + 至少 1 张新插画（R11）。哪张插画对应哪个稀有度另定。长期改为分页网格。 | 卡牌、图鉴 |
| D7 | MVP 里要不要番茄钟 | 只在主视野的工具栏里放番茄钟图标，具体功能先不做。点击时弹短提示"即将推出"。 | W8 |
| D8 | UI 整合方式 | Plan A：由 Devanshi 的 Canvas 调用我们的功能。Plan B 启动器保留作为备选。决定前先在真机上核实清晰度：把 Devanshi 的 Canvas 界面和我们现有的 HUD 放在眼镜上对比（文字、图标边缘、插画）。如果 Canvas 发糊，先排查常见原因再定：Canvas 缩放 / 参考分辨率不是 640×480、World Space 的 Dynamic Pixels Per Unit 太低、贴图被压缩或开了 Mipmap、渲染分辨率缩放（eyeTextureResolutionScale）小于 1、文字没用 TextMeshPro。修不好就以 Plan B 的 HUD 为底，只搬 Canvas 的美术素材。在开始做 HUD 模块前决定。 | InputAdapter/HUD |
| D9 | 时间来源 | 真实时钟跟着眼镜的系统时间走（内部用 UTC 计算离开时长，避免时区和夏令时跳变）。IdleCore 和 OfflineProgress 只通过一个可注入的时钟读时间（`IGameClock`：真实时钟、测试时钟），代码里不直接到处调用 `DateTime.Now`。系统时间被往回调时，经过时间按 0 算（W2）。演示模式不改时间，只给收益乘倍率（9.2b）。必须在做 W1/W2 之前定下来，之后再改成本很高。 | W1、W2、9.2b |
| D10 | Reset 还是存档槽 | MVP 做 Reset（放在设置里，二次确认）。SaveSystem 内部按 slotId 存，MVP 固定用 slot 0，演示模式用另一个槽位；3 个存档槽的界面留到 v2。 | W2、W9 |
