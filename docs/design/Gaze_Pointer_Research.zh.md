日期：2026 年 11 月 21 日。分支：`Yaxin-Mu/Prototype-2`。状态：调研完成，待定项 A–D 已决定（第 4 节），测试场景已搭建（5.9），首次设备测试通过（第 6 节）。

## 1. 问题

游戏在 RayNeo X3 Pro 上运行时，视野正中一直有一个小点。主 HUD 用滑动（移动焦点）和单击（确认）操作，这个点在那里没有用处，反而让画面显得杂乱。

问题：
1. 这个点是什么？能不能隐藏？
2. 在藏宝图上，“转头对准、镜腿单击执行”这种选物方式好不好用？

## 3. 发现

### 3.1 这个点是什么
- 它是 SDK 的凝视指针 `LaserBeamDot`，属于 `Editor/GameSceneBuilder` 放进设备场景的 `XR Plugin` prefab。它跟随头部朝向，不跟随眼睛：眼睛往旁边看时，点不会动。
- Qualcomm 教程列出了 prefab 的组成：`LaserBeam` = 与相机对应的射线控制单元；`BeamGraphic` = 射线渲染器，标注“可禁用”；`LaserBeamDot` = 射线与物体碰撞处的交互点。教程没有给出隐藏 `LaserBeamDot` 的步骤。
- 游戏用的是 `XR Plugin.prefab`，其中的 `LaserBeam` 位于闭源的 `UnityXRSDKCore.dll`。另一个 prefab `XR Plugin Gaze.prefab` 使用 `GazeLaserBeam.cs`：指针在物体上停留一段时间后会自动点击（停留进度环）。游戏没有用它，测试也不能用（不做停留确认）。

### 3.2 为什么一直显示
- 游戏里没有任何代码隐藏它。唯一的隐藏代码在旧的 AnchorZone 调试 HUD（`AnchorZone/ZoneDebugHUD.cs`）里，而且只在锚点菜单打开时生效。
- 这段代码找到名为 `LaserBeamDot` 和 `BeamGraphic` 的 renderer，在 `Camera.onPreCull` 中（每帧绘制前）把它们关掉。注释说明了原因：闭源的 `LaserBeam` 可能在自己的 update 里重新打开 renderer，所以只在 Inspector 里取消勾选一次并不可靠。

### 3.3 指针已经能作用到我们的 UI
- 每个游戏 canvas 都挂了 `XRGraphicRaycaster`（`UI/UiFactory.cs`，`CreateCanvas`）。因此 SDK 射线会命中我们的 HUD 和地图图形，点就画在命中位置。
- Qualcomm 教程说，canvas 上挂了 `XRGraphicRaycaster` 后，点击镜腿应能触发按钮事件。也就是说，SDK 会把自己的点击发给点所在的 UI 元素。
- 目前这没有影响，因为游戏里没有 Unity `Button`，也没有 `IPointerClickHandler`：所有输入都走我们的 `InputAdapter`。如果把测试物体做成按钮，一次镜腿单击就会执行两次：一次来自 SDK 点击，一次来自 `InputAdapter`。这是最主要的输入冲突风险。

### 3.4 无指针交互是常见做法
- MultiSet README 说它的应用没有指针：UI canvas 挂在头部相机下面，所以 LaserBeam / EventSystem 的射线无法稳定命中按钮。所有输入都靠触控板：滑动移动高亮，单击激活，双击返回。这和我们的主 HUD 一致。README 没有提到如何隐藏 SDK 的点。

### 3.5 触控板时序（ARDK 源码，`SimpleTouchForLite.cs`）
- 间隔小于 `MulitTapSpacing` = 0.4 s 的点击会合并：2 次 = 双击（我们的全局返回），3 次 = 三击。
- 单击要等 0.4 s 窗口结束后才上报，所以每次单击都在手指抬起约 0.4 s 后才到达游戏。
- `OnTouchStart` 在手指按下时立即触发，没有延迟。

### 3.6 当前地图行为（`UI/TreasureMapView.cs`）
- 地图在身体右侧 55°、视线下方约 8°、距离 2.9 m 处。只有当头部偏航角离开“身体左侧 35° 到地图外侧 25°”这个范围并持续 1.5 s，地图才会移动。看地图时，地图永远不动。
- 目前的“地图在视野内”= 到地图的水平偏航夹角小于 20°（只看偏航，不看俯仰，没有滞回）。在视野内时，地图接收 Prev / Next / Confirm，用于宝箱焦点。
- 尺寸估算（未在设备上实测）：600 × 464 px 的地图约占视野 15–16° × 12°，约每度 39 地图像素；地图上任一点离中心都在约 10° 以内。

### 3.7 结论
- 这个点是 SDK 凝视指针。可以在每帧绘制前关掉它的 renderer 来隐藏（`ZoneDebugHUD` 已验证此方法）；背后的输入模块照常运行。
- 建议默认：所有地方都隐藏。只在“对准”本身就是交互的地方显示指针，下面的测试就是验证这一点。

## 4. “对准选择”测试方案审阅

结论：**可以做成独立测试场景**，需按下表修改。所有数值仍是初始值，待设备上调整。

| # | 主题 | 修改或说明 |
|---|---|---|
| 1 | 用哪个指针（已决定 C） | 测试场景里 SDK 的点始终隐藏，在地图 canvas 上画我们自己的准星（我们自己画的指针）（青色圆环，≥ 2 px）。原因：SDK 的点是闭源的，会自己重新打开，还会落在 HUD 上；我们自己的准星能严格按显示/隐藏表执行。不做 SDK 点的对比开关。 |
| 2 | 命中检测 | 自己做命中检测：从头部相机发射线 → 地图平面 → 地图坐标 → 目标命中区域。不用 SDK 指针事件。测试物体不能是 `Button` 或 `IPointerClickHandler`，避免一次单击执行两次（3.3）。 |
| 3 | 地图视角夹角 | 用头部前方与地图中心之间的完整 3D 夹角（当前的 `InView` 只看偏航）。进入：< 15° 并持续 0.2 s。退出：> 20°。所有目标离中心都在约 10° 以内，在到达退出边界前都能对准。地图边缘到 15° 之间，准星不在地图上，算作空白处。 |
| 4 | 目标大小 | 命中区域直径约 2.5°（约 100 地图像素），间隔至少 1.5°（约 60 px）。600 px 的地图能放下三个目标，并留出一块明确的空白区。需在设备上复核。 |
| 5 | 地图锁定 | 现有跟随规则已经保证玩家看地图时地图不动。仍按方案要求，在地图视角开启时加一个明确的锁定。 |
| 6 | 单击目标（已决定 A） | 在 `OnTouchStart`（手指按下）时记下准星下的目标；单击到达时，如果仍在地图视角，就对这个目标执行。同时记录按下时的目标和单击到达时的目标，设备测试就能看出两者不一致的频率。 |
| 7 | 单击延迟（已决定 D） | 不在本轮范围内：本轮测试对准，不测响应速度。SDK 触控设置保持不变（所有地方都是 0.4 s 双击窗口）。单击在手指抬起约 0.4 s 后到达；决定 A 以按下时的目标为准，所以这段延迟不会选错物体。大约每秒单击一次。 |
| 8 | 输入分发（已决定 B） | 主视角 = 滑动移动焦点，单击确认，没有准星，也没有点。地图视角 = 只用准星：不用滑动选择（滑动被忽略），准星选中物体，镜腿单击确认。对准 handler 在地图视角开始时压入 `InputAdapter` 栈，结束时出栈；地图视角期间它吞掉所有单击和滑动，包括点在空白处的，所以工具栏收不到（T05）。面板压在它上面并接管输入（T11）。 |
| 9 | 旧宝箱逻辑 | 测试地图没有宝箱，测试场景里 `TreasureMapView` 的宝箱焦点输入保持关闭，所以不会有“旧地图选择逻辑”抢走单击。 |
| 10 | 头部追踪丢失 | 使用 `SlamSessionController.OnTrackingChanged`（漂移保护：头部速度 > 3 m/s 视为丢失；本设备上 `GetSlamStatus()` 不可用）。丢失时：退出地图视角，清除高亮，忽略单击。 |
| 11 | 暂停 / 恢复 | 在 `OnApplicationPause` 时：退出地图视角，清除目标和按下时的快照（T13）。 |
| 12 | 隔离 | 新场景 `AimTest.unity`，像设备场景一样由编辑器菜单生成，不放在 Build Settings 第一位；有自己的 APK 构建触发器。计数只存在内存里（不写存档），所以正式存档不会被动到。对共享代码的修改都是可选开启的（地图锁定开关、宝箱输入关闭开关），在主游戏里不生效。 |
| 13 | 日志 | 每个事件一行日志，标签 `[AimTest]`：进入/退出地图视角及夹角、目标切换、按下时目标、单击目标、结果、被忽略的单击及原因。这样设备日志就能回答 T01–T13。 |
| 14 | RayNeo 规范 | 青色高亮，绿色表示成功，不用红色（没有破坏性操作）。文字 ≥ 16 px；结果文字放在顶部提示区或目标旁边；提示文字要短。双击始终是返回，不用于玩法。 |

决定（Yaxin，2026 年 11 月 21 日）：
- **A. 单击目标：** 手指按下时准星下的目标。
- **B. 两个视角，两种选择方式：** 主视角（工具栏）= 只用滑动选择，没有准星，SDK 的点隐藏。地图视角 = 不用滑动选择，只用准星：准星下的物体高亮，镜腿单击一次确认。
- **C. 准星：** 只用我们自己的准星。
- **D. 单击延迟：** 不在本轮测试范围内；触控设置保持不变。

### 4.1 关于双击和 0.4 s 延迟的说明（留待以后）
- 双击 = 返回（RayNeo 规范）。它来自 `Assets/XR/RayNeoGeneralSettings.asset` 中的 SDK 触控设置 `MulitTapSpacing: 0.4`（SDK 默认值，从未改过），以及 `InputAdapter`：它把 `OnDoubleTap` 转成 `GameAction.Back`；面板返回或关闭，新手引导会询问 “Skip tutorial?”。
- 因为一次单击可能是双击的第一下，SDK 要等 0.4 s 才上报。这就是每次单击的延迟。
- 地图视角里没有可以“返回”的东西（离开地图视角靠转头），所以以后的版本可以在那里关闭双击窗口，得到即时单击。不属于本次测试。

## 5. 测试方案（按约定内容，并加入上述修改）

### 5.1 目标
在眼镜上验证这套流程是否自然、准确：
转向地图 → 准星出现 → 对准物体 → 物体高亮 → 镜腿单击 → 执行动作 → 转回主视角 → 准星隐藏。
本轮只测选择，用测试物体和计数器。不做真正的采集、建造或经济。

### 5.2 场景
保留主视角 HUD 和右侧地图。地图上放三个测试物体，彼此距离足够远：

| 物体 | 对准时的提示 | 单击结果 |
|---|---|---|
| 树木 | Tree · Tap to collect | 树木闪一下，显示 “Wood +1” |
| 石块 | Rock · Tap to mine | 石块闪一下，显示 “Stone +1” |
| 建筑底座 | Site · Tap to build | 变成简单建筑，显示 “Built” |

树木和石块可以反复使用。建造完成后，对准显示 “Building · Tap to inspect”，单击显示 “Inspected”。地图上留一块明确的空白区用于空点测试。提供一个测试用 Reset 入口，恢复建筑底座和计数。

### 5.3 视角与指针规则

| 状态 | 准星 | 高亮 | 滑动 | 镜腿单击 |
|---|---|---|---|---|
| 主视角 | 隐藏（SDK 的点也隐藏） | 无 | 移动工具栏焦点 | 和现在一样操作主 HUD |
| 地图视角，对准空白处 | 显示 | 无 | 忽略 | 地图上不执行；工具栏也收不到 |
| 地图视角，对准物体 | 显示 | 该物体 | 忽略 | 执行该物体的动作 |
| 面板、奖励窗口或确认框打开 | 隐藏 | 清除 | 面板 | 只作用于面板 |
| 离开地图视角 | 隐藏 | 立即清除 | 回到主视角 | 不对旧物体执行 |

地图视角 = 头部朝向与地图中心的夹角（不是眼动追踪）。< 15° 并持续 0.2 s 进入，> 20° 退出。地图视角期间地图不重新居中；退出后恢复正常跟随规则。玩家对准时地图永远不动。

### 5.4 选择与反馈
- 对准 = 准星在物体命中区域内：青色描边，显示名称和动作提示。此时还不执行。
- 确认 = 镜腿单击：执行手指按下时所对准物体的动作（决定 A）。
- 移到另一个物体，高亮跟着移动；移到空白处，高亮清除。最多只有一个物体高亮；重叠时，射线先命中的物体优先。
- 单击成功时有一次短暂的绿色闪烁和结果文字。文字不需要单击关闭，也不抢输入焦点。
- 准星已经离开的目标，单击时绝不响应。只看不点永远不会执行（没有停留确认）。
- 动作动画播放期间，物体显示 “Working…” 并忽略单击；单击不会排队。

### 5.5 完整流程示例（树木）
1. 看正前方：主 HUD，没有准星。
2. 向右转到地图：满足进入规则后，准星出现，地图停止重新居中。
3. 对准树木：出现描边和 “Tree · Tap to collect”。
4. 单击：树木闪一下，木材 +1，显示 “Wood +1”。
5. 继续对准：闪烁结束后，树木可以再次使用。
6. 对准石块：树木失去高亮，石块获得高亮。
7. 转回去：准星、高亮和提示消失；主 HUD 重新接收输入。

### 5.6 输入冲突规则
- 地图视角下，一次单击只给地图；绝不同时给工具栏或旧宝箱逻辑。
- 主视角下，地图忽略单击，即使刚刚对准过某个物体。
- 打开的面板接管输入。
- 双击在所有地方都保持全局返回的含义；在地图上，它绝不会采集、建造，也不算作两次单击。
- “Working…” 期间的单击被忽略，不会排队。不要快速连点：大约每秒一次。
- 头部追踪丢失：停止地图操作并清除高亮；恢复后重新检查目标。

### 5.7 功能测试
记录通过 / 失败、发生了什么，以及问题由什么触发。

| ID | 操作 | 预期 |
|---|---|---|
| T01 | 启动，停在主视角，头部小幅左右转动 | 没有准星；主 HUD 正常 |
| T02 | 主视角 → 地图 → 主视角，重复 5 次 | 准星按规则显示和隐藏；没有残留高亮 |
| T03 | 在地图视角边缘缓慢来回转头 | 小幅转头不会闪烁；超过退出夹角后隐藏 |
| T04 | 依次对准树木、石块、建筑底座 | 只有当前物体高亮；名称和动作对应正确 |

| T11 | 打开面板，看向地图，单击 | 只有面板响应；地图无高亮、无动作 |
| T12 | 在地图视角停留 30 s，依次看三个物体 | 地图从不重新居中，也不跟随准星 |
| T13 | 暂停或关闭应用，再恢复 | 不执行旧动作；没有残留高亮 |

### 5.8 真人体验测试
对测试者只说这一句，不多解释：“看你右边的地图。采集一个木材、一个石头，然后在建筑底座上建造。”

观察：
- 他们是否理解准星是用来对准的？
- 能否分清“高亮”和“已完成”？
- 是否知道要镜腿单击来确认？
- 会不会误选相邻物体？
- 是否需要明显用力才能保持头部稳定？
- 转回来后，主视角是否显得干净？
- 他们会不会在地图上尝试滑动？（地图上滑动会被忽略。）

然后做一轮计时测试：按指定顺序选择三个物体，共 10 次单击。记录首次选择正确、空点和误执行次数。

第一轮通过标准：
- 10 次中至少 9 次首次选择正确。
- 零重复执行，零主视角误执行，零次双击触发动作。
- 使用 2–3 分钟后，询问对准是否累、转头是否不舒服。
- 如果没通过，先调整目标大小、间距和地图位置，再考虑更复杂的交互。
